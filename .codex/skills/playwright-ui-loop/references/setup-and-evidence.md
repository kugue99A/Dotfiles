# Setup and evidence reference

## Codex CLI + Chrome DevTools MCP

Use Chrome DevTools MCP to inspect an already-open authenticated Chrome tab:

```toml
[mcp_servers.chrome-devtools]
command = "bunx"
args = ["chrome-devtools-mcp@latest", "--autoConnect"]
```

In Chrome 144 or newer, open `chrome://inspect/#remote-debugging`, enable remote debugging, and approve the incoming connection. Prefer this user-approved auto-connect flow over launching the normal profile with `--remote-debugging-port`.

Use Chrome DevTools MCP for live DOM, computed styles, console, network, screenshots, and performance evidence. Use Playwright for repeatable actions and regression assertions.

## Codex CLI + Playwright MCP

Prefer a user-scoped MCP entry when Playwright browser work should be available in every repository. On this machine, use Bun:

```toml
[mcp_servers.playwright]
command = "bunx"
args = ["@playwright/mcp@latest", "--browser=chrome"]
```

The skill includes `scripts/setup-browser-mcps.sh`, which registers both browser MCP entries through `codex mcp add` without copying the rest of `~/.codex/config.toml` into Dotfiles. It leaves an existing entry unchanged.

The default persistent profile keeps login state per workspace. Use `--user-data-dir` only when a deliberately shared test profile is required. Use `--isolated` with `--storage-state` for deterministic test sessions.

After changing Codex MCP configuration, start a new CLI session and confirm the Playwright tools are available before relying on them.

## Authentication

Prefer this order:

1. Dedicated Playwright test account and scripted setup.
2. One-time manual login in the Playwright persistent profile.
3. `storageState` generated by an auth setup test.
4. Existing-browser CDP only when the user explicitly requires that session and accepts the browser restart/profile implications.

Store auth state under an ignored path such as `playwright/.auth/`. Treat it as a secret because it can contain impersonation-capable cookies and headers. Include IndexedDB when the application stores authentication there.

## Evidence snippet

Adapt this inside Playwright MCP code execution or a repository-local diagnostic script:

```ts
const evidence = await locator.evaluate((element) => {
  const rect = element.getBoundingClientRect();
  const style = getComputedStyle(element);
  const parent = element.parentElement;
  const parentRect = parent?.getBoundingClientRect();

  return {
    tag: element.tagName,
    rect: {
      x: rect.x,
      y: rect.y,
      width: rect.width,
      height: rect.height,
    },
    parentRect: parentRect
      ? {
          x: parentRect.x,
          y: parentRect.y,
          width: parentRect.width,
          height: parentRect.height,
        }
      : null,
    computed: {
      display: style.display,
      position: style.position,
      width: style.width,
      height: style.height,
      minWidth: style.minWidth,
      minHeight: style.minHeight,
      maxWidth: style.maxWidth,
      maxHeight: style.maxHeight,
      overflow: style.overflow,
      aspectRatio: style.aspectRatio,
      objectFit: style.objectFit,
      gridColumn: style.gridColumn,
      gridRow: style.gridRow,
    },
  };
});
```

For containment regressions, compare edges rather than rounded widths alone:

```ts
expect(child.x).toBeGreaterThanOrEqual(parent.x - tolerance);
expect(child.y).toBeGreaterThanOrEqual(parent.y - tolerance);
expect(child.x + child.width).toBeLessThanOrEqual(
  parent.x + parent.width + tolerance,
);
expect(child.y + child.height).toBeLessThanOrEqual(
  parent.y + parent.height + tolerance,
);
```

Use a small tolerance only for subpixel layout. Record the chosen tolerance and reason.

## Trace and screenshot policy

For durable Playwright Test coverage:

```ts
use: {
  trace: "retain-on-failure",
  screenshot: "only-on-failure",
}
```

During active debugging, capture a named before screenshot before editing and an equivalent after screenshot after the fix. Keep generated evidence out of source control unless the repository intentionally versions visual snapshots.

## CDP limitations

Modern Chrome restricts remote debugging against the normal default user-data directory. Prefer a dedicated Playwright profile. If an existing authenticated Chrome session is mandatory, explain the limitation before requesting permission to close or relaunch the browser. Never silently kill the user's browser or copy a sensitive profile.
